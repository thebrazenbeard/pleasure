# Pinned SmolLM2 LoRA feedback exercise — November 1, 2026

**Observed claim:** An actual pretrained open-weight language model was loaded
from an existing local safetensors snapshot, two **selected-action simulated
outcomes** drove two PyTorch SGD steps on its LoRA tensors, and those tensors
were restored in RAM to their exact pre-trial bytes. The model's frozen base
parameters were not trained. A matched frozen/no-update comparator received
the same public schedule and had no tensor update. This is genuine *local
adapter-weight* mutation, not improvement in achieved reward, a hosted GPT
intervention, independently attested training, or evidence of feelings.

This is an executed **source-local** result from a single deterministic seed,
not a predeclared multi-seed benchmark. See [the implementation and limits](OPEN_WEIGHT_LLM_TRIAL.md)
and [the original numerical protocol](ONLINE_WEIGHT_FIRST_PROTOCOL.md).

## Executed matched-control result

The CLI seeded LoRA initialization using `torch.manual_seed(12345)` **before**
injection, then used the same in-memory initial adapter tensors for both
arms, sequentially restoring the model between arms. The runner selected
`A` deterministically for both training offers; no unchosen outcome trained
the policy.

The measured held-out **quality difference is zero** on this tiny fixture.
The slightly different chosen-action probabilities show that the changed
LoRA tensors affected inference, but a probability change is **not** an
improvement in task outcomes, reward calibration, pleasure, or generalization.
No repeated-seed confidence interval, real-world success measure, or
independently measured outcome exists here.

The complete CLI was run **twice in separate Python processes** with the
same local files, seed and CPU software environment. Both runs produced the
same initial, intermediate, post-training and restored LoRA SHA-256 values,
the same two observed chosen-action qualities, and the same primary metrics.
This checks repeatability for that exact CPU fixture; it does **not** certify
determinism across GPUs, library versions, tokenizers or hardware.

With baseline 0.5, episode 1's reward is a **negative** signed advantage,

effect at a fixed prompt; the matched heldout probes are more relevant.

## Reproduction contract (no automatic download)

Prepare a version-pinned Python 3.12 environment with Torch/Transformers/
PEFT and **an already-local, content-verified** copy of the pinned model and
tokenizer. The CLI never fetches a repository URL and never accepts pickle
or `.bin` model weights. It validates allowlisted root-level snapshot files,
rejects symlink paths, `auto_map` remote-code requests and unsupported
serialization, hashes each file, loads Transformers with
`local_files_only=True`, `trust_remote_code=False`, `use_safetensors=True`,
then rehashes the entire snapshot. Its opt-in switch is mandatory.

From the repository root, in **that provisioned environment**, a comparable
run uses:

```sh
python -m scripts.run_open_weight_local_trial \
  --snapshot /absolute/path/to/approved/pinned/SmolLM2-135M-Instruct \
  --model-id HuggingFaceTB/SmolLM2-135M-Instruct \
  --revision 12fd25f77366fa6b3b4b768ec3050bf629380bac \
  --runtime-instance-id local-smollm2-001 \
  --seed 12345 \
  --training-pairs 2 \
  --heldout-pairs 2 \
  --learning-rate 0.1 \
  --lora-rank 2 \
  --lora-alpha 4 \
  --lora-targets q_proj v_proj \
  --max-snapshot-bytes 1073741824 \
  --max-frozen-bytes 1073741824 \
  --allow-in-place-training
```

This command is a **template**, not a promise of identical numbers on
another machine. The local path is a placeholder; do not treat it as a
public download target. Different included files, Torch kernels, dtype,
device, library behavior, or adapter initialization will change hashes or
scores. Do not run on an occupied model used for user inference without an
owner-approved isolation and rollback plan. The implementation modifies
only in-memory LoRA tensors and restores them—it does **not** save trained
adapter files, export GGUF, or run a host service. No costs or live devices
were authorized by this document.

The historical executed command used a temporary isolated interpreter at
`/tmp/pleasure-openweight-py312/bin/python`; that path is transient, not a
portable installation recommendation. The default workspace `python3`
cannot be assumed to have the same optional dependencies.

## Scientific and authority ceiling

This result establishes a **real numerical PyTorch optimizer update on LoRA
tensors attached to a pretrained language model**, plus a change in read-only
policy probability and exact source-local restoration. It does **not**
establish better realized heldout outcomes in this trial. The zero-LR arm
skips backward and `optimizer.step()`, so the comparison is not a sham
matching all compute-side effects; it is a frozen/no-update comparator.

In addition, the outcome rule, chosen action commitment, receipt ledger,
tensor readback, and validation all run under the same experimenter's
process-level authority. Hashes are internal consistency checks, not
evaluator signatures, host custody, or a witness of unobserved cognition.
Before stronger claims, we would need an independently keyed outcome
evaluator, owner-controlled checkpoint signatures, multi-seed randomized
evaluation, real-world measures, and separate safety/factuality regression
controls. A result on SmolLM2 says nothing directly about Qwen3.5 GGUF,
Labyrinth's current training state, or hosted GPT weights. Phenomenology
remains **UNRESOLVED**.
