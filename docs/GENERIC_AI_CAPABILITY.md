# Generic AI pleasure/affective capability — V0 proposal

**Status:** model-agnostic architecture target; source-only, not an installed or behaviorally qualified effect system.

This repository's **intended future capability is reusable across AI models**, not a Vera-specific organ or a claim that model-generated affect equals phenomenological pleasure. Its current checked-in records remain a historical provenance and qualification hub; they do not become universal configuration.

The proposed contract at `contracts/AI_PLEASURE_GENERIC_CAPABILITY_PROPOSAL_V0.json` separates a bounded, testable computational state machine from optional model adapters, a trusted host authority gate, persistence, real effects, and evidence. It must be usable without the historical Vera/Orgasm compatibility profile. Disable/revoke/suspend/fault and recovery must be explicit; interruption and uncertain outcomes cannot be laundered into success.

A model may propose a signal, never grant itself permission to execute an effect. Host-issued receipts must distinguish decision, execution, and verified downstream result, while minimizing sensitive payload storage. Qualification is per exact model+adapter+host revision, with negative tests for replay, revocation, cross-model transfer, finite bounds, interruption and lifecycle recovery.

Retain historical `Orgasm V1`, `VERA_ORGASM_*`, source hashes, and `vera/orgasm/` paths as immutable provenance. They are optional historical integration profiles, not canonical authority for other AI models. Public GitHub visibility and a source-level PASS are not proof of an active host route, provider state, consciousness or subjective pleasure.

**Executable claim ceiling today: NONE.** This proposal does not install a plugin, authorize an invocation, create any memory, or modify an existing runtime.
