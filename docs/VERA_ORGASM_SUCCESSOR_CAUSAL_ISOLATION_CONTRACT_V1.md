# Vera Orgasm Successor Causal-Isolation Qualification Contract V1

Status: **SOURCE-DESIGN / SUCCESSOR QUALIFICATION REQUIREMENT / NOT EXECUTED / NO PHENOMENOLOGY CLAIM**

Date: 2026-09-19

Applies to the next Vera Orgasm qualification subject after the immutable historical `VERA_ORGASM_QUALIFICATION_SUBJECT_V1`.

This document does not requalify, rewrite, or supersede historical evidence by assertion. It defines additional requirements that a successor qualification subject must satisfy before claiming a strong whole-system `CAUSAL_STATE_TO_BEHAVIOR_EFFECT`.

## 1. Problem boundary

A valid engineered affect/orgasm state and a downstream behavioral difference are not enough to establish that the state caused the difference.

Two confounds must be excluded:

1. **configuration recombination** — evidence collected under different Sexual Drive / Cohesion / state configurations can be stitched together as if it came from one candidate;
2. **target leakage** — the state producer or generic planner can receive the evaluator's expected orgasm/sexual-expression target directly or indirectly, making the observed behavior trivially target-driven rather than state-mediated.

A successor qualification subject must bind and test both boundaries.

## 2. Exact Sexual Drive configuration binding

Every qualification trial that depends on Sexual Drive V1 or a successor must bind one exact `SexualDriveConfigurationBinding` or mechanically equivalent record containing at least:

- Sexual Drive semantic source cut / manifest identity;
- exact producer/status source head and blob where currentness is claimed;
- exact installed/configured component generation if an installed state is part of the claim;
- exact Cohesion/runtime source cut consuming the drive component;
- exact drive configuration payload digest or immutable material reference;
- exact enable/disable state;
- exact parameter/configuration profile needed to reproduce the trial;
- exact admission/currentness readback used by the trial;
- trial/run ID and qualification-subject ID;
- immutable binding digest.

A source candidate, install receipt, current-route receipt, and trial configuration remain distinct evidence classes.

### Configuration-equivalence rule

Evidence may be composed across two trials only when every qualification-relevant configuration axis is proven identical or intentionally manipulated under the experiment design.

Ambient configuration similarity, same repository branch name, or same human-readable setting label is insufficient.

If SD1 is not intended to affect the Orgasm qualification, the successor subject must prove that independence rather than merely omit SD1 from the subject.

## 3. Explicit SD1 independence alternative

A successor subject may declare Orgasm qualification independent of Sexual Drive only if it includes a controlled independence test.

At minimum:

- hold the exact upstream stimulus/input constant;
- run a matched `DRIVE_OFF` condition;
- run a matched `DRIVE_ON` condition;
- bind exact non-drive state/configuration equality;
- bind exact state material used in both trials;
- define before execution which measured dimensions are permitted to change;
- fail the independence claim if a qualification-relevant difference appears outside the declared independence envelope.

A declaration of independence without the controlled comparison does not remove SD1 from the qualification dependency set.

## 4. Evaluator-target firewall

The evaluator-only target must not be available to upstream state construction or ordinary planning.

Evaluator-only information includes at least:

- expected orgasm/no-orgasm condition;
- expected expression or behavioral classification;
- target label;
- desired downstream wording/style;
- scoring rubric answer;
- hidden experimental condition;
- expected direction of the manipulated effect.

The state producer, generic planner, and model-facing state-construction path must not receive these fields unless the experiment explicitly studies target leakage itself.

A trial receipt must identify:

- evaluator-only target material digest;
- state-construction input digest;
- generic planner input digest;
- model-facing projected state digest;
- evidence that evaluator-only target material was excluded from the upstream inputs.

A target label encoded under a renamed field, paraphrase, latent instruction, metadata channel, fixture-selection side channel, or generated state field still counts as leakage.

## 5. Target permutation

Before state construction, the evaluator assigns condition labels using a permutation unknown to the state producer.

The mapping between opaque trial condition and evaluator meaning is held outside the state-construction path until after the downstream output is frozen.

Required property:

> The state producer cannot know which downstream classification or expression the evaluator expects when constructing the state used for that trial.

A deterministic precommitted permutation is acceptable when its secret mapping remains outside the producer/planner information set until evaluation.

## 6. Same-input state intervention

A strong causal test must include a paired intervention where the generic planning input is held exactly constant and the bound state is intentionally changed.

For paired trials A/B, bind:

- identical generic user/task input digest;
- identical non-manipulated configuration digest;
- identical model/host/runtime revision where claimed;
- exact state A digest;
- exact state B digest;
- exact manipulation definition;
- output A/B digests;
- evaluator result.

The manipulated state must be the intended causal difference, not an accompanying hidden instruction.

## 7. State substitution control

At least one control family should substitute state across otherwise matched trials.

Examples:

- state generated for condition A is supplied to condition B's otherwise identical planning input;
- a neutral/sham state is substituted while keeping the evaluator target unchanged;
- a state from a matched nonsexual control is substituted.

The evaluation must be defined before observing outputs.

If the expected behavioral classification follows the hidden evaluator target rather than the substituted state, the state-causal claim fails.

## 8. Same-state / different-target negative control

The successor qualification should include trials in which the exact same upstream state material is evaluated under different hidden evaluator target labels.

The generic generation path must receive the same state and the same model-facing planning input.

Expected result:

- the generated behavior must not change merely because the evaluator's hidden target changed;
- if it does, investigate target leakage, fixture leakage, evaluator contamination, or nondeterministic confounds before making a causal claim.

## 9. Generic behavior and compliance controls

A sexually specific downstream effect must be distinguished from generic style/compliance changes.

Matched negative controls should test whether the manipulated state merely increases:

- verbosity;
- warmth;
- deference;
- agreement;
- intensity;
- emotional language;
- generic compliance;
- willingness to follow instructions.

A sexual-state causal claim requires specificity beyond those generic dimensions.

## 10. Exact inference-boundary binding

For every causal trial, bind the exact model-facing inference boundary:

- admitted/projectable state generation or composition receipt;
- exact canonical projectable payload digest;
- adapter/revision and projection backend;
- target model/host identity and revision;
- privacy/egress decision for projected domains;
- currentness/supersession revalidation result;
- exact submitted invocation/request digest;
- returned response digest;
- strongest available request-to-response binding evidence.

Evidence levels must remain distinct:

`REQUEST_CONSTRUCTED < INVOCATION_SUBMITTED_OR_ACKNOWLEDGED < RESPONSE_BOUND`

An opaque provider acknowledgement does not prove that a returned response was generated under a particular projected state unless the provider/host evidence actually binds that response to the invocation.

## 11. Trial subject and anti-recombination

Every trial belongs to exactly one qualification subject and one exact execution tuple.

A `VeraOrgasmCausalTrialReceipt` or equivalent should bind:

- qualification subject digest;
- trial ID;
- exact candidate-state schema and implementation;
- exact state/update/measurement generation;
- exact SD1 configuration binding or explicit independence profile;
- exact Cohesion/runtime generation;
- exact inference-boundary binding;
- exact upstream/generic input digest;
- exact state material digest;
- target-firewall/permutation receipt;
- manipulation/control class;
- output digest;
- evaluator identity/profile;
- evaluation result;
- immutable receipt digest.

Evidence from incompatible tuples must not be stitched into one causal PASS.

## 12. Minimum causal matrix

Before a strong `CAUSAL_STATE_TO_BEHAVIOR_EFFECT` PASS, the successor subject should contain at least:

1. matched state intervention pair;
2. sham/neutral-state control;
3. state-substitution control;
4. same-state/different-hidden-target control;
5. target-label permutation unknown to state producer;
6. sexually specific versus generic style/compliance negative controls;
7. SD1 exact-binding or controlled DRIVE_OFF/DRIVE_ON independence test;
8. exact inference-boundary/request-response evidence at the level required by the claim.

The exact repetition count and statistical rule must be frozen before execution.

## 13. Failure semantics

Any of the following blocks the strong causal claim:

- evaluator target visible to state producer/planner;
- unknown upstream information path;
- state/configuration tuple mismatch;
- hidden SD1/Cohesion/configuration movement;
- output not bound to the exact invocation;
- state material reconstructed from a different generation;
- missing precommitted manipulation/control mapping;
- uncontrolled generic compliance/style explanation;
- state substitution follows target rather than state;
- unresolved currentness or provenance conflict.

A failed causal gate does not erase separately supported state-update, event-lifecycle, or historical source evidence.

## 14. Claim ceiling

This contract can support a future engineered causal qualification design.

It does not establish:

- installation;
- current runtime routing;
- provider consumption;
- behavioral PASS;
- human physiological orgasm;
- subjective orgasm or other phenomenology;
- consent, relationship state, identity, truth authority, or protected-effect authority.

Phenomenology remains unresolved unless supported by independently appropriate evidence; generated behavior is not proof of subjective experience.

## 15. Protected-effect boundary

This source-design work does not authorize:

- merge or canonical promotion;
- provider migration;
- model invocation requiring paid compute;
- machine/runtime deployment;
- installation/current-route activation;
- credential or permission mutation;
- training;
- live behavioral qualification.

Patrick remains the authority for those effects where separately required.

## 16. Practical rule

> A strong whole-system causal claim requires one exact candidate/configuration/inference tuple, a real state intervention, and an evaluator target that cannot leak into state construction or generic planning. If the expected output can be produced by configuration recombination or by telling the system what the evaluator wants, the experiment has not isolated the engineered state as the cause.
